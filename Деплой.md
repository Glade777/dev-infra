# Taskflow (Task Manager) — опис та деплой

Вебзастосунок для керування задачами (створення, редагування, видалення, зміна статусу `TODO` / `IN_PROGRESS` / `DONE`, дедлайни, пошук та фільтрація).

## Архітектура проєкту

- **`frontend/`** — React 19 + Vite 6. У Docker збирається у статику та роздається через **Nginx** (`frontend/nginx.conf`), який проксіює `/api/` на контейнер `backend:8080`.
- **`backend/`** — Java 21 + Spring Boot 3.4.5 + Spring Data JPA (REST API `/api/tasks`, `/api/health`).
- **`db`** — MySQL 8.0 (схема таблиць оновлюється автоматично через `spring.jpa.hibernate.ddl-auto=update`).

---

## Варіант 1. Запуск і деплой через Docker Compose (рекомендовано)

Файл `docker-compose.yml` підіймає всі три сервіси (`db`, `backend`, `frontend`) в одній мережі `app-network`, очікує готовності MySQL через `healthcheck` та зберігає дані БД у volume `mysql_data`.

> За використання Docker Compose ручні кроки з налаштування системного MySQL (`172.25.0.1`, `mysqld.cnf`, `ufw`) та окремих команд `docker run` **не потрібні**.

### 1. Підготовка змінних оточення (опціонально для тесту, обов'язково для продакшену)

У `docker-compose.yml` задані стандартні значення для швидкого локального старту (`task_manager`, `taskapp`, `password`, порт `80`). Щоб задати власні паролі або порт, створи `.env` у корені проєкту:

**Linux / macOS:**
```bash
cp .env.example .env
```

**Windows (PowerShell):**
```powershell
Copy-Item .env.example .env
```

Відредагуй `.env` (особливо `DB_PASSWORD` і `MYSQL_ROOT_PASSWORD`).

### 2. Збірка та запуск

З кореневої директорії `Team2_DevOps2026`:

```bash
docker compose up -d --build
```

Перевірка статусу та логів:

```bash
docker compose ps
docker compose logs -f backend
```

Після запуску сайт буде доступний на порту `80`:
- локально: `http://localhost/`
- на сервері / ВМ: `http://<IP_сервера>/`
- перевірка API: `http://localhost/api/health` → `{"status":"UP"}`

Зупинка:

```bash
docker compose down      # зупинити контейнери (дані БД зберігаються у volume mysql_data)
docker compose down -v   # зупинити контейнери та повністю видалити дані БД
```

### Важливі зауваження щодо CORS та портів

1. **Порт фронтенда (`FRONTEND_PORT`)**: у `frontend/nginx.conf` прописано `proxy_set_header Host $host;` (без номера порту). Якщо запускати на порту `80` (`http://localhost` або `http://<IP_ВМ>`), усе працює з коробки. Якщо змінити порт (наприклад `FRONTEND_PORT=8085`), на запитах `POST`/`PUT`/`DELETE` може спрацювати CORS-обмеження Spring Boot — у такому разі потрібно або додати відповідний origin (`http://localhost:8085`) у `backend/src/main/java/com/example/taskmanager/config/WebConfig.java`, або замінити `$host` на `$http_host` у `frontend/nginx.conf`.
2. **`server_name` у `frontend/nginx.conf`**: зараз там вказано `192.168.1.105`. Оскільки це єдиний `server`-блок на порту `80`, Nginx відповідає на будь-який хост/IP, але для охайності можна замінити на `server_name _;`.
3. **Фаєрвол на ВМ**: якщо деплоїш на віддалений сервер, переконайся, що порт `80` (або обраний `FRONTEND_PORT`) відкритий для вхідного трафіку. Порт `3306` у `docker-compose.yml` за замовчуванням не публікується назовні.

## Варіант 2. Локальний запуск для розробки (без Docker для бека і фронта)

Потрібні **Java 21**, **Maven**, **Node.js 18+** і **MySQL 8** (можна підняти лише контейнер `db`, розкоментувавши `ports: - "3306:3306"` у `docker-compose.yml` та запустивши `docker compose up -d db`).

### Backend

У директорії `backend/`:

**Linux / macOS:**
```bash
cp .env.example .env
# заповнити DB_* у .env
set -a; source .env; set +a
mvn spring-boot:run
```

**Windows (PowerShell):**
```powershell
$env:DB_HOST="localhost"
$env:DB_PORT="3306"
$env:DB_NAME="task_manager"
$env:DB_USERNAME="taskapp"
$env:DB_PASSWORD="password"
mvn spring-boot:run
```

API запуститься на `http://localhost:8080`.

### Frontend

У директорії `frontend/` (обов'язково передати `VITE_API_URL`, бо у `vite.config.js` немає проксі для `/api`):

**Linux / macOS:**
```bash
npm install
VITE_API_URL=http://localhost:8080/api npm run dev
```

**Windows (PowerShell):**
```powershell
npm install
$env:VITE_API_URL="http://localhost:8080/api"
npm run dev
```

Фронтенд буде доступний на `http://localhost:5173` (цей origin уже дозволений у `WebConfig.java`).

## Варіант 3. Ручний деплой на Linux VM (без Docker Compose, MySQL на хості)

> Це попередня ручна схема деплою, коли MySQL встановлений безпосередньо на хості ВМ, а бекенд і фронтенд запускаються окремими `docker run`.

Перед початком білду потрібно змінити `WebConfig.java` для правильного CORS origin:

```java
.allowedOrigins(
    "http://localhost:5173",
    "http://192.168.1.105" // замінити на IP ВМ
)
```

Також перевірити `frontend/nginx.conf`:

```nginx
server {
    listen 80;
    server_name _;

    root /usr/share/nginx/html;
    index index.html;

    location /api/ {
        proxy_pass http://backend:8080;

        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

### 1) Налаштування БД на хості

```sql
CREATE DATABASE IF NOT EXISTS task_manager;
CREATE USER 'taskapp'@'%' IDENTIFIED BY 'password';
GRANT ALL PRIVILEGES ON task_manager.* TO 'taskapp'@'%';
```

Створити мережу, щоб бекенд з контейнера міг підключатися до MySQL на хості:

```bash
docker network create \
  --driver bridge \
  --subnet 172.25.0.0/24 \
  --gateway 172.25.0.1 \
  mysql-java
```

Змінити `bind-address` у `/etc/mysql/mysql.conf.d/mysqld.cnf`:

```ini
bind-address = 172.25.0.1
```

Перезапустити MySQL та відкрити порт у `ufw`:

```bash
sudo systemctl restart mysql
sudo ufw allow from 172.25.0.0/24 to 172.25.0.1 port 3306 proto tcp
```

Створити файл оточення `/etc/task-manager/team2.env`:

```env
DB_HOST=172.25.0.1
DB_PORT=3306
DB_NAME=task_manager
DB_USERNAME=taskapp
DB_PASSWORD=пароль
```

### 2) Білд образів і мережа додатку

```bash
cd backend
docker build -t java_back-image:1.0 .

cd ../frontend
docker build -t frontend-image .

docker network create app-network
```

### 3) Запуск контейнерів

```bash
docker run -d \
  --name backend \
  --network mysql-java \
  --env-file /etc/task-manager/team2.env \
  java_back-image:1.0

docker network connect app-network backend

docker run -d \
  --name frontend \
  --network app-network \
  -p 80:80 \
  frontend-image
```
